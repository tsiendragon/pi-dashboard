## sudo 参数错误先拒绝，不再让用户修授权框

- 配套扩展提交 `ded48f4c53de2f09c6aca0207851e8727f035ddc` 强化 `sudo_exec` 参数说明和必填 reason。执行前校验字段类型、绝对路径、NUL、256 项 argv / 16000 UTF-8 字节上限，并预检可执行文件、工作目录及 sudo；扩展内无效参数返回带字段名的 `invalid_sudo_parameters`，供 agent 修正，不产生授权请求、不执行命令。schema 无效输入由宿主先返回参数错误。
- 预检不运行目标、不验证程序专用选项、解释器或 sudoers/PAM，不保证实际执行成功，也不消除 TOCTOU。待批准参数复制冻结；预检期间断连/换会话后，即使重连也不会补发旧授权。
- Android 修复实时事件漏接 sudo；初始缺少说明、无效或已过期的请求不显示授权密码框，仅尝试取消一次，不提交密码、不自动重试。取消未确认时仅提示连接问题。
- **当前工具没有必填 reason 表示仍加载旧定义，不能只安装 APK：用户须 `/reload` 后，让 agent 以完整参数重新申请。旧宿主仅返回其原有取消错误，字段级校验需要新扩展。**
- 有效命令仍必须由用户单次明确批准，沿用 HTTPS 专用密码通道、安全窗口及绑定原始 argv 的执行方式，不改 sudoers，不开放免密或以 root 运行 Dashboard。

## 生效方式

同签名覆盖安装 APK；本机本地扩展源码由用户 `/reload` 加载。App 更新本身无需重启 Dashboard；Web 的快捷面板由用户执行 `./run.sh` 或自己的启动方式构建部署，选择合适时间以免中断活跃会话。agent 未重启服务、未重载当前会话，也未发布扩展 npm 包。
