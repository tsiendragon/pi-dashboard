# PiDash Android 5.21 · build 52

Debug 预发布版；尚未完成真机验收。

## 通知点开就是那条会话

- 以前点通知只打开 App 首页，还得自己找回那条会话；现在通知里带上机器与进程标识，点击直接进入对应会话（App 在后台、已关闭、从通知冷启动三种情况都覆盖）。
- 同一会话的通知仍然只有一条，切走再点回来依旧是同一条会话；请求码按会话生成，不会因为多条通知而复用到错误的 Intent。
- 消费过 extra 后会立即移除，旋转屏幕或系统恢复页面不会重复跳转。

## 宽屏阅读宽度

- 会话正文在平板/展开态手机上不再拉满整行：超过 680 dp 时左右自动留白，正文回到可读宽度（`ProseMaxWidth` 从"定义了没用"变成真的在用）。
- 会话列表同样在超过 720 dp 时居中，卡片不会横跨整块屏幕。

## 文案统一

- 「已发送重载扩展指令」「已发送重载指令」统一为「已重载扩展」；失败提示统一为「重载扩展失败」。
- 重启确认框去掉 `⚡` 前缀与「会话」，与菜单项一样叫「重启 Pi 进程？」。

## 验证与限制

- 编译通过；JVM 单测 **213 项**（新增 1 项断言：通知必须带着 backendId 才能深链）全部通过；签名与固定证书一致。
- 未做真机验收：通知冷启动跳转、返回栈是否符合预期（点通知进入会话后按返回应回到列表）、以及平板上的留白比例，都需要在设备上确认。
