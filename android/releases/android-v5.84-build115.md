# Android 5.84 (build 115)

## 语音输入：跨轮回调隔离

- 每次开始录音都会开启一次新的会话轮次，并安装该轮次自己的 WebSocket 回调。
- 上一轮迟到的识别结果、失败/关闭回调、超时或润色结果不再能改写当前这一轮的状态和草稿：
  点取消后紧接着重新开始，不会再被上一轮的迟到文字污染。
- 录音、发送、结束只作用于本轮持有的 socket 与录音器，不再依赖类级共享字段。

## 语音输入：停止竞态

- 点停止时先在音频锁内认领「本轮的录音段」，只有在会话仍然存活时才真正发送 `finish`。
- 若停止的瞬间 socket 已经断开（`finish` 发不出去），不再空等一个永远不会到来的 `finished` 帧，
  而是直接用已识别的文字收尾并进入润色。
- `finish`/`fail` 的回调即使在发送过程中就把这一轮收回空闲态，界面也不会被重新置成「整理文字」。

## 语音输入：连接超时

- 新增连接阶段超时：socket 打开后迟迟收不到服务端 `ready`（服务器不可达、上游握手卡住）时，
  不再让输入框永远停在「连接中」，而是报错回到可重试状态。
- 连接、转写、润色三个期限集中为一处可测试的配置（默认 15s / 15s / 35s）；
  本次只增加连接期限，转写与润色期限的取值未变。

## 服务端：ASR context 初始化

- `/api/asr/realtime` 的 `session.update` 现在整条连接只发一次：首个上下文帧在握手前后到达都只用于这一次配置。
- 此前上下文帧晚于上游握手时会再补发一次 `session.update`，在已经开始送音频之后重设会话，
  可能让服务端丢掉这段录音的识别；现在迟到的上下文被接受并忽略，不会中途重置会话。
- 需要更新并重启后端（由你自己执行 `./run.sh`）才能得到这条修复；只覆盖安装 APK 不包含服务端改动。
