结论先说：只需要改一个已经存在的弹窗，不动页面布局

会话页右侧本来就有一个「目标」按钮（在“中断 / 压缩 / 重载”旁边），点开是一个居中弹窗，点空白处或按 Esc 关闭。 所以弹窗形态已经存在，不需要新增页面元素；这次要做的只是把弹窗里面的内容补齐。
  • 弹窗打开时页面被半透明遮罩盖住，关闭后完全恢复原样 —— 会话页布局一行都不用改。
  • 唯一动到列表的地方：左侧会话列表加一个小角标（下图第 6 条），不占布局，只是文字后面加个「2/5」。
  • 弹窗宽度从 512px 放宽到 672px，因为工作项要露出来、内容变多；如果嫌宽可以保持 512px 但会滚动更多。

现状弹窗 vs 建议增强 · 逐条差异

项目现状（点「目标」看到的）建议增强
工作项（完成度）藏在「更多详情」折叠里，默认看不见，要手动展开两层提到外面、默认可见，带状态和依赖 —— 这是本次的核心改动
进度角标没有。要自己数标题栏显示「2/5 完成」
需要你处理的事阻塞项里混在一起，要自己读处置字段标题栏显示「1 项需要你处理」，并把这类阻塞项置顶标黄
清单过期提醒没有。目标已完成、工作项还全是「待做」也照常显示黄色提醒 + 一个「让 agent 同步清单」按钮
历史会话会话关掉后，按钮不可点，什么都看不到能打开，标注「只读快照」，按钮换成「在新会话里继续」
没有设目标时弹窗里一片「—」，等于没说空状态说明 + 「让 agent 起草目标 + 清单」
会话列表没有任何进度提示文字后加角标：4/4、2/5、! 需核对、— 没目标
进度摘要 / 当前工作分成两个独立区块，内容有重复合并成「当前在哪一步」（上一轮小结收进去）
目标原文已在，保持原样保持原样（不摘要、不改写）
验收标准 / 约束 / 来源文档已在「更多详情」里保持原样，仍在「更多详情」里

数据从哪来（什么都没新增）

  • 全部来自会话记录里已经存在的目标状态：目标原文、工作项、验收标准、阻塞项、来源文档。
  • 「2/5 完成」= 工作项里状态为「已完成」的条数 / 总条数，是算出来的，不需要 agent 额外维护。
  • 「需要你处理」= 阻塞项里处置为「需要用户协助」的条数，也是算出来的。
  • 过期提醒靠两条现成信息推断：目标状态 + 工作项状态是否为空。不猜内容。

请你确认三件事

  • 弹窗宽度：512px（现状）还是 672px（本原型）？放宽是因为工作项要直接看到。
  • 验收标准要不要能逐条打勾：现在的数据里没有单条状态，本原型老实标注了「未逐条核对」。要打勾就得让 agent 每次额外维护，属于加负担。
  • 清单过期后做什么：只提醒（本原型）／提醒并让 agent 自动重排／提醒并允许你手工勾选。
