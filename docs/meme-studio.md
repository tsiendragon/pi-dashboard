## 持久化与历史（2026-10-20）

- 目标：让结果、历史记录和请求生命周期不再跟页面绑定。
- 默认保存位置：`~/.pi/dashboard/memes`，可用 `MEME_OUTPUT_DIR` 覆盖，支持 `~/` 前缀，目录不存在时自动创建。目录里是 `jobs.json`（历史索引，最多 500 条）和每张图一个文件（`<id>.png|jpg|webp`）。索引写坏时会另存为 `jobs.corrupt-<时间>.json`，不静默覆盖。
- 请求生命周期：`POST /api/memes/generate` 只做校验和建记录，通过后返回 `202` 与 `running` 记录；真正的第三方调用在服务进程里继续，浏览器刷新、切页、关标签都不影响。前端在有运行中任务时每 2.5 秒刷新历史，任务结束后停止；窗口重新聚焦时再刷一次。
- 单飞与恢复：同一服务进程同时只允许一单，第二单返回 `429` 并带上正在跑的记录。服务重启后，磁盘上仍是 `running` 的记录会在下次读取时标记为 `failed`，并提示去服务商账单核对。
- 落盘策略：供应商返回 base64 时直接解码写入；返回临时链接时，仅当链接是 HTTPS 且域名与被调用接口同域（含子域）才由服务端下载保存，否则保留链接并提示会过期，不做任意 URL 代理。
- 新增接口：`GET /api/memes/jobs`（返回 `{ jobs, outputDir }`）、`GET /api/memes/jobs/:id`、`GET /api/memes/images/:id`（支持 `?download=1`），全部要求浏览器认证；id 不合法或文件缺失返回 404。
- 粘贴上传：页面监听粘贴事件，剪贴板里有图片文件时直接当作参考图，纯文本粘贴不受影响；复用 `frontend/src/utils/clipboardFiles.ts`。
- 验证：`npx vitest run --config vitest.backend.config.js backend/__tests__/memes.test.ts`（34 项，覆盖落盘、历史、单飞、到期恢复、跨域链接拒绝、认证与路径穿越）；`npm --prefix frontend run test -- --run src/test/MemeStudioPage.test.tsx`（19 项，覆盖历史渲染、后台任务刷新、粘贴上传、临时链接下载）；`npm run typecheck:backend`、`npm run typecheck:frontend`、`npm run docs:env-check`。
- 清理边界：索引只保留最近 500 条记录，更早的图片文件不会自动删除；需要腾空间时由用户自行清理目录。写索引失败只记录日志，不会中断已经付费的生成。
